# 通常の日記 AI 編集 — ローカル実装レビュー

基準: main `2f9332f`、作業ブランチ `feature/diary-editable-ai`。2026-10-14に、記載の送信範囲・予算条件でGitHub送信、本番反映、有効化の承認を受領。実AIの代行実行・記事公開は対象外。

## 操作と保護

箇条書きメモ → 明示的な生成 → 編集可能な候補 → 「本文に使う」 → 編集可能な本文 → 従来の公開確認。
生成は公開を行わない。生成中の編集、記事切替、取消、タイムアウト後の遅延応答は破棄する。
既存本文の置換と候補の再生成は確認する。編集中の本文を復元データで上書きしない。
画面を開く際に既存の記事ID・写真をリセットしない。写真と既存下書きの保存方式は変更しない。
入力は別の sessionStorage キーに一時保存する。タブ終了後の永続保存・写真のバックアップではない。

## 有効化条件と送信範囲

`DIARY_AI_ENABLED=1` と既存APIキー、Productionのownerフルセッション、同一Origin、CSRF一致が必要。
初期値は無効。単発試験のフラグ・消費マーカーは変更しない。
OpenAIへ送る本文は、その操作で入力したメモ、固定の編集指示のみ。付随設定は `model`、`max_output_tokens:1200`、`store:false`、`stream:false`、`truncation:disabled`、`service_tier:default`。
タイトル、既存本文、写真メモ、画像本体、LINE履歴、StudioのCookie/CSRFトークン、requestIdはOpenAIへ転送しない。ただしメモへ本人が書いた氏名・住所等もそのまま送信される。自動匿名化や個人情報除去はない。
サーバーのOpenAI APIキーはHTTPS AuthorizationヘッダーとしてOpenAIへ送る。ユーザーのパスワードやStudio認証情報とは別である。
ブラウザ→自サイトAPIはメモとrequestId、同一サイトCookieとCSRFヘッダー。サービス側の保持条件を `store:false` による消去保証とは扱わない。
メモにない事実を追加しない指示を含むが、内容の正確性は保証できないため本人の確認を必須とする。

## 費用・利用記録

固定モデル `gpt-4.1-mini-2025-04-14`。入力6000トークン以下（ローカル計数に1024を加算）、出力1200以下。
入力 $0.40/100万、出力 $1.60/100万を基準に1回 **$0.00432** を事前予約する。
全owner共通で6回/10分、30回/24時間、300回/30日。予約予算は $0.15/24時間、$1.50/30日。
回数上限による最大予約額はそれぞれ $0.1296、$1.296。暦月ではなく直近30日。
税込・為替・Netlify費用・他機能のOpenAI利用を含まない。価格変更時には再確認が必要。
モデル廃止予定日の2027-01-14以降は無効。別モデルへの自動切替はしない。

強整合の専用Blobsストア `smile-diary-ai-usage` にCASで予約し、同一requestIdの再送を拒否する。
保存対象は操作ID・時刻・予約額・完了状態・実測トークン・推定費用。メモ・候補・セッションは保存しない。
取消、通信失敗、不明な応答でも予約額を返還しない。自動再送しない。記録不能時は閉じた状態で停止する。
保持期間は直近30日（更新時に整理）。利用結果の不明な予約も制限に算入する。

## 再レビューでの修正

- 詳細画面の既存記事を簡易日記が誤って上書きする可能性を防止。既存の詳細編集がある場合は簡易画面を開かず、詳細画面での保存・編集継続を案内する。記事IDや詳細本文が変わった後は公開前に停止する。内容を自動統合する機能はない。
- 同時リクエストで後発予約があると先発の結果記録が失敗する条件を修正。未来時刻は各予算枠へ保守的に含める。
- requestIdの文字列型を必須化しUUIDの大文字小文字を正規化。別表記での重複送信を防ぐ。
- メモ内の個人情報も送信されること、30日上限を画面で明示。

全インスタンスで同一ストア/キーを使い、強整合読取とETagのIf-Match/If-None-Matchで予約する。CAS競合時だけ最大8回まで再読取・再計算する。これはAIリクエストの再送ではない。SDKの実ヘッダーと412応答をモック検証済み。未知の書込結果はAI送信せず停止する。
ブラウザ取消後もサーバー処理は継続し得るが、予約は送信前に保存済みで払い戻さない。失敗・タイムアウト・結果記録失敗も予約枠に残る。実Netlifyの複数インスタンス負荷試験は未実施で、サービス側の強整合/CAS契約を前提とする。
変更差分・ビルド成果物を確認して配備する。Production / Functionsの非秘密設定は `DIARY_AI_ENABLED=1`、単発試験は `DIARY_AI_TRIAL_ENABLED=0` を維持。既存の `OPENAI_API_KEY` は読取・変更せず利用する。
Production判定は既存のビルドスクリプトが生成するproductionスタンプを使用する。ビルド専用の `CONTEXT` がFunctions実行時に存在することには依存しない。Previewではスタンプがfalseとなり停止する。
元のDesktop checkoutは変更しない。ロールバックはこの追加差分を除去し通常AIフラグを無効にする。
既存の日記下書き/画像・単発試験のマーカーを削除しない。
